2. Pembagian sistem

HIS — pusat orkestrasi

Program, periode, roster, aturan reminder, akses provider IHC, request treatment, penjadwalan sesi, pelaksana admin, laporan sesi, dan penutupan treatment dikelola di HIS.

APPS — perpanjangan tangan

Perusahaan dan peserta memakai APPS untuk monitoring, persetujuan, input mandiri, permintaan treatment, riwayat, dan evaluasi. IHC hanya memakai jalur pengiriman hasil yang diberikan.

Alur ringkas: IHC mengirim hasil → HIS menyimpan dan menghitung level terbaru → HR mengevaluasi/request → Admin HIS menjadwalkan dan menjalankan sesi → laporan kehadiran/kedisiplinan tersedia untuk HR dan peserta.

3. Langkah UAT Super Admin / Admin HIS

3.1 Buka Orkestrasi Wellness

  1. Masuk sebagai akun pengelola.
  2. Buka domain HIS.
  3. Pilih Program Kesehatan Korporat → Orkestrasi Wellness.
  4. Pastikan tiga tab tersedia: Peserta & pelaksanaan, Konfigurasi program & roster, dan Impor hasil.

Workspace HIS menampilkan program, peserta, level terbaru, request treatment, sesi, laporan, dan akses provider.

3.2 Buat program dan roster

  1. Buka tab konfigurasi.
  2. Buat program dengan corporate, kode, nama, tanggal, dan status Pilot.
  3. Impor roster menggunakan employee_id tetap dan email terverifikasi.
  4. Jalankan sinkronisasi roster.
  5. Impor ulang file yang sama; pastikan tidak membuat peserta ganda dan jumlah inserted/skipped benar.

Employee ID adalah kunci. Jangan menggantinya dengan NIK otomatis jika Employee ID tersedia.

3.3 Beri akses provider IHC

  1. Buka panel Akses pemasok hasil IHC.
  2. Tambahkan user dengan role ihc dalam tenant yang sama.
  3. Pilih program yang boleh dikirimi hasil.
  4. Cabut akses setelah pengujian dan pastikan upload berikutnya ditolak.

4. Langkah UAT IHC

4.1 Login sebagai pemasok hasil

  1. Pilih mode IHC · Pemasok hasil.
  2. Buka Impor Hasil IHC.
  3. Pastikan hanya program yang diberi akses yang muncul.
  4. Pastikan menu pengaturan program, treatment, dan riwayat peserta tidak tersedia.

IHC mengirim hasil dengan provenance, checksum, status batch, dan validasi baris.

4.2 Preflight dan batch

  1. Unggah CSV valid.
  2. Pastikan employee_id, waktu ukur, nilai, konteks, dan external_id dikenali.
  3. Uji baris Employee ID tidak dikenal, nilai di luar rentang, pasangan tensi tidak lengkap, dan checksum duplikat.
  4. Pastikan baris invalid ditolak per baris dan batch yang sama tidak menggandakan observasi.

5. Langkah UAT Peserta

5.1 Consent dan input mandiri

  1. Masuk sebagai peserta.
  2. Buka Program Wellness Saya.
  3. Baca notice wellness-privacy-v2; checkbox harus kosong.
  4. Tanpa consent, pastikan input mandiri ditahan oleh UI dan server.
  5. Centang dan setujui. Masukkan tekanan darah dan gula darah sintetis.
  6. Pastikan label sumber self reported / unverified muncul.

Peserta melihat hasil pribadi, jadwal, laporan sesi, kehadiran, kedisiplinan, tindak lanjut, dan kesimpulan treatment.

5.2 Penarikan consent

  1. Tarik persetujuan dari halaman peserta.
  2. Pastikan request dan sesi aktif dibatalkan, reminder berhenti, dan request baru ditolak.
  3. Pastikan riwayat pribadi tetap dapat dibaca dan audit trail tidak dihapus.

6. Langkah UAT HRD

6.1 Monitoring hasil terbaru

  1. Masuk sebagai HRD.
  2. Buka Monitoring Wellness.
  3. Pastikan daftar peserta termuat otomatis.
  4. Gunakan pencarian nama/Employee ID dan filter level.
  5. Masukkan dua hasil sintetis pada waktu berbeda, misalnya 170/105 lalu 115/75. Level harus mengikuti hasil terbaru, sedangkan kedua hasil tetap ada di riwayat.
  6. Gula nonpuasa harus diberi tanda perlu tinjauan; jangan diperlakukan otomatis sebagai gula puasa.

HR melihat hasil individual karyawan dalam corporate sendiri. Level adalah label operasional, bukan diagnosis.

6.2 Request treatment

  1. Pilih satu atau beberapa peserta yang consent-nya aktif.
  2. Pilih jenis treatment, label, jadwal usulan, dan catatan.
  3. Kirim request.
  4. Pastikan request muncul sebagai Diminta di workspace HIS.
  5. Kirim ulang payload yang sama; pastikan tidak ada request ganda.

Tampilan mobile menyediakan filter peserta, level terbaru, request treatment, dan ringkasan pelaksanaan tanpa overflow halaman.

6.3 Evaluasi laporan

  1. Buka Hasil & sesi pada peserta.
  2. Periksa jadwal, kehadiran: hadir/terlambat/tidak hadir/izin.
  3. Periksa kedisiplinan: mengikuti/sebagian/tidak mengikuti/belum dinilai.
  4. Periksa laporan, tindak lanjut, dan kesimpulan.
  5. Unduh laporan sesi CSV untuk evaluasi internal.

7. Langkah Admin HIS untuk treatment

7.1 Siklus sesi

  1. Terima request: Diminta → Diterima admin.
  2. Buat sesi bernomor dan pilih admin pelaksana.
  3. Ubah jadwal atau batalkan sesi dengan alasan bila diperlukan.
  4. Setelah sesi berlangsung, isi laporan, kehadiran, kedisiplinan, dan tindak lanjut.
  5. Buat sesi pengganti jika peserta tidak hadir.
  6. Selesaikan treatment hanya setelah seluruh sesi terlapor dan simpan kesimpulan.

Contoh treatment selesai: satu sesi dilaporkan, kehadiran dan kedisiplinan terlihat, tindak lanjut serta kesimpulan tersimpan.

8. Kriteria lulus dan catatan rilis

Wajib lulus

Tenant isolation; consent v2; level memakai data terbaru; riwayat tidak hilang; request idempotent; laporan tidak dapat ditimpa; HR/admin/peserta melihat cakupan sesuai peran; IHC hanya dapat upload pada program yang diberikan.

Bukti lokal

46 pemeriksaan PGlite end-to-end, browser Edge untuk HR → HIS → peserta → IHC, screenshot desktop/mobile, dan audit menu/security suite. Semua data pengujian sintetis.

Catatan provisioning. Seed akun lama masih mendefinisikan uat.ihc@avahealth.sbs sebagai super_admin. Sebelum UAT berikutnya, ubah profil akun itu menjadi ihc dan beri akses program dari HIS. Jangan menjalankan ulang seed lama setelah migrasi orkestrasi diterapkan.
