Panduan Registrasi Klinik Utama Moksa

Persiapan HIS, LIS, operasional klinik, dan inventory dari pendaftaran tenant sampai siap digunakan.

Tenant: klinik-utama-moksaMode: dedicated databaseFokus: HIS · LIS · Operasional · Inventory
Status dokumen: panduan implementasi dan UAT. Nilai domain, repository, database, dan akun pengguna diisi setelah ada keputusan resmi Klinik Utama Moksa. Jangan menaruh password atau service key di dokumen ini.

1. Data yang perlu disiapkan

Identitas fasilitas

  • Nama legal dan nama operasional
  • Alamat, kontak, jam layanan
  • Nomor izin dan penanggung jawab
  • Logo dan identitas brand

Kontak implementasi

  • Admin klinik
  • Penanggung jawab medis
  • Penanggung jawab laboratorium
  • Penanggung jawab gudang/farmasi

Konfigurasi teknis

  • Domain tenant
  • Repository dedicated
  • Database dedicated
  • DNS, SMTP, dan storage

2. Registrasi tenant di AVA Tech

1
Buka menu Tenant, Lisensi & Health → Tenant & Klien Faskes.
Buat tenant baru dengan kode moksa atau kode resmi yang disepakati.
2
Isi profil fasilitas.
Masukkan nama, jenis fasilitas Klinik Utama, alamat, timezone Asia/Jakarta, dan status Staging.
3
Hubungkan deployment dedicated.
Isi domain dan repository yang sudah disetujui. Referensi secret menggunakan nama environment seperti MOKSA_DATABASE_URL, bukan nilainya.
4
Aktifkan modul.
Aktifkan HIS, LIS, operasional, inventory, audit, dan tenant monitoring. Wellness, IHC import, dan treatment tetap nonaktif sampai ada kebutuhan.

3. Setup HIS

Master data

  • Cabang, ruang, poli, loket, dan lokasi pelayanan
  • Dokter, perawat, analis, kasir, admin, dan user pengelola
  • Jenis kunjungan, penjamin, tarif, paket, dan metode pembayaran
  • Alur pasien: pendaftaran → pemeriksaan → order → hasil → billing → pulang

Validasi awal

  1. Buat satu pasien sintetis.
  2. Daftarkan kunjungan rawat jalan.
  3. Input SOAP/vital sign secara uji.
  4. Buat order laboratorium dari HIS.
  5. Pastikan status dan identitas order terbaca di LIS.

4. Setup LIS

Katalog dan alur pemeriksaan

  • Master pemeriksaan, kode internal, LOINC, UCUM, spesimen, wadah, dan stabilitas
  • Reference range terpisah menurut usia, jenis kelamin, operator, batas bawah, dan batas atas
  • Panel dipecah menjadi analit individual
  • Lokasi penerimaan, worklist, validasi hasil, komentar, dan approval dokter
  • Aturan critical value dan jalur notifikasi

Uji integrasi HIS–LIS

Gunakan pasien sintetis dan satu order. Pastikan tidak ada duplikasi, hasil kembali ke encounter yang benar, dan perubahan status meninggalkan audit trail.

6. Inventory dan gudang

  • Buat lokasi gudang, ruang penyimpanan, dan titik stok
  • Daftarkan obat, reagen, bahan habis pakai, alat kesehatan, satuan, dan pemasok
  • Atur batch, nomor lot, tanggal kedaluwarsa, minimum stock, dan reorder point
  • Catat penerimaan, pemindahan, pemakaian, retur, penyesuaian, dan stock opname
  • Gunakan FEFO untuk item berkedaluwarsa
  • Hubungkan pemakaian reagen dengan pemeriksaan LIS bila proses sudah disepakati
Kontrol minimum: stok tidak boleh berubah tanpa sumber transaksi, actor, waktu, alasan, dan referensi dokumen.

8. UAT sebelum go-live

  1. Login tiap role dan uji pembatasan akses.
  2. Uji satu alur pasien dari pendaftaran sampai billing.
  3. Uji order HIS → LIS → hasil tervalidasi → kembali ke HIS.
  4. Uji stok masuk, pemakaian, FEFO, stok minimum, dan opname.
  5. Uji gagal simpan, timeout, false success, dan akses terputus.
  6. Pastikan error masuk ke AVA Tech Report dengan correlation ID.
  7. Uji backup dan restore drill di staging.
  8. Tandatangani berita acara UAT dan daftar gap.

9. Cara provisioning domain, repository, dan database

1
Tetapkan domain tenant.
Contoh: moksa.avahealth.sbs atau domain milik klinik. Jangan memakai domain produksi sebelum DNS dan pemilik domain menyetujui perubahan.
2
Buat project/repository dedicated.
Buat repository khusus Moksa atau gunakan template AVA yang dikunci versinya. Catat URL repository pada konfigurasi tenant, misalnya MOKSA_REPOSITORY.
3
Buat database dedicated.
Provision project database terpisah untuk Moksa. Jalankan migration inti sesuai urutan, lalu migration HIS, LIS, inventory, audit, monitoring, dan telemetry. Simpan URL database dan key di secret manager.
4
Isi environment variables deployment.
Di hosting project Moksa, tambahkan MOKSA_DATABASE_URL, MOKSA_SUPABASE_ANON_KEY, MOKSA_SUPABASE_SERVICE_ROLE_KEY, MOKSA_TENANT_ID, dan MOKSA_INSTALLATION_ID. Nilai secret tidak ditulis ke file JSON atau source code.
5
Hubungkan domain ke hosting.
Tambahkan domain pada project hosting, lalu buat record DNS yang diminta provider (umumnya CNAME untuk subdomain atau A/ALIAS untuk apex). Tunggu status TLS/SSL menjadi valid.
6
Set konfigurasi tenant.
Perbarui config/tenants/klinik-utama-moksa.json: deployment.domain, deployment.repository, environment, dan status fitur. File ini hanya berisi metadata non-secret.
7
Deploy dan verifikasi.
Buka domain, login dengan akun admin yang dibuat melalui jalur resmi, cek tenant context, HIS, LIS, inventory, audit, heartbeat, dan error report. Catat hasilnya di berita acara UAT.
Urutan aman: buat database → jalankan migration → isi secret environment → deploy repository → hubungkan DNS → verifikasi TLS → buat user → UAT. Jangan membalik urutan dengan mengirim service key ke browser atau memasukkannya ke repository.

9. Checklist go-live

Teknis

  • Domain dan TLS aktif
  • Database dedicated siap
  • Backup terjadwal
  • Monitoring heartbeat aktif

Operasional

  • Role dan user disetujui
  • SOP alur pasien tersedia
  • SOP LIS dan inventory tersedia
  • Kontak eskalasi ditetapkan

Mutu

  • Master data disetujui
  • Reference range diverifikasi
  • UAT lulus
  • Risiko dan gap memiliki owner
Catatan data: seluruh contoh UAT wajib sintetis. Data pasien nyata hanya digunakan setelah dasar hukum, perjanjian, kontrol akses, retensi, dan prosedur insiden disetujui.
